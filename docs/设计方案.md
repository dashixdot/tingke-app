## 一、项目背景与目标

传统听课本靠手写，课堂环节与时间难以精确对应，复盘时回忆模糊、评课缺少客观时间证据。本 App 在听课过程中以"计时 + 一键打标"的方式，自动在时间轴上记录每个课堂环节的发生时刻与类型，听课结束即时生成带时间戳的课堂环节时间轴，用于个人反思、组内评课与"好课标准"研讨。

**目标**
1. 降低打标操作成本——单次打标 ≤3 秒、单手可完成。
2. 标签贴合物理课真实环节，且可标记"亮点 / 不足 / 疑问"供评课。
3. 听课结束即可导出时间轴（文本 / CSV），可直接粘贴进听课本或教研记录。

## 二、目标用户与使用场景

- **用户**：中学物理教师、教研组长、实习教师、视导 / 评课专家。
- **场景**：随堂听课、公开课 / 示范课观摩、跨校教研、师徒结对听评课。
- **设备**：安卓手机（竖屏单手操作），建议 Android 8.0+。

## 三、核心功能清单

| 模块 | 功能 | 说明 |
|---|---|---|
| 听课管理 | 新建 / 继续 / 结束 / 历史 | 填写课题、授课教师、班级、听课人、日期、节次、人数、地点；结束后自动存档进历史，可回看 |
| 计时 | 开始 / 暂停 / 继续 / 结束 | 真实计时，毫秒级时间戳打标 |
| 打标 | **一键打标（主交互）** | 计时页底部常驻 14 个环节标签坞，轻点即按当前时刻写入，无需弹窗与保存；长按可补充子标签/评课标记/备注 |
| 录音 | **开始前默认开启** | 开始页「同时录音」默认勾选、可取消；开始听课即同步录音，暂停跟录 |
| 标签体系 | 常用环节标签 | 见第四节，支持子标签与评课标记 |
| 时间轴 | 抽屉式实时列表 | 不离开计时页即可上滑查看，可改/删 |
| 复盘 | 报告页（默认「环节占比」） | 三级 Tab：环节占比 / 文本时间轴 / CSV |
| 导出 | CSV / 长图 / 复制 | CSV 带 UTF-8 BOM 可直接进 Excel；占比长图用于教研组群分享 |

> **v1.1 新增**：① 同步录音——与计时同步开始，可暂停跟录、结束生成可回放/下载音频，作为回听取证；② 时间轴实时显示每个环节的持续时长；③ 结束后按主标签聚合给出各环节**时长 + 百分比**占比（条形图），用于课堂结构复盘（如导入/新授/实验/检测/小结的时间分配是否合理）。

> **v1.2 新增 / 变更**：① 录音改为**开始前默认勾选**（可取消），不再需要进入听课后再点一次；② 打标由"弹窗填表"改为**常驻标签坞一键打标**，并支持 5 秒内撤销；③ 打标时刻**在点击瞬间冻结**，不随填写耗时漂移；④ 计时页常驻「当前环节 + 上一条」；时间轴改抽屉、不切页；⑤ 结束自动存档进**历史记录**，不再覆盖；⑥ 报告页默认「环节占比」，新增未打标行、CSV 下载、占比长图导出；⑦ 支持深/浅色主题、震动反馈、平板两栏适配。

- 亮点 ⭐
- 不足 ⚠️
- 疑问 ❓

每个标记可附一句备注（如"用激光笔 + 水槽演示折射，直观"）。

## 七、关键交互流程

1. **新建听课**：填课题 / 教师 / 班级 / 听课人 / 日期（均允许留空，结束前可补）。
2. **开始计时与录音**：点「开始听课」→ 大号计时器运行，同时启动同步录音（需授权麦克风）；计时暂停则录音一并暂停跟录。
3. **打标**：点底部大按钮 → 弹窗显示环节标签网格 → 选主标签（可选子标签与评课标记）→ 填备注（可选）→ 保存。系统以"保存瞬间时间 − 开始时间"作为时间戳。
4. **时间轴与环节时长**：实时按时间排序，每条标记同步显示该环节持续时长（= 下一标记时间 − 本标记时间；末段计至结束时刻）；可删除标记（删除后相邻时长自动重算）。
5. **结束与占比**：停表并停止录音，跳转报告页——可回听/下载录音、查看文本时间轴、CSV（含环节时长），并切换「环节占比」页：按主标签聚合，输出每环节「时长 + 百分比」与条形图。
6. **导出归档**：复制文本 / 导出 CSV（含环节时长）/ 保存录音文件。

## 八、UI 设计要点（移动端）

- 竖屏单手优先：**标签坞固定在底部操作栏上方**（拇指可达区），不放在屏幕上半部。
- 一键打标：轻点标签 = 立即写入时间戳；长按 = 展开子标签/评课标记/备注。打标后 5 秒内可从 toast 撤销。
- 计时器字号大、状态文字与运行态严格同步（运行 / 已暂停 / 已结束 / 待开始），避免"数字在走但显示待开始"的矛盾。
- 打标弹窗只承担"补充/修改"，标题明确显示**已冻结的打标时刻**，并注明"不会随保存时间变化"。
- 时间轴用抽屉（Drawer）而非切页，保证大计时器始终可见；左时间轴样式：时间 + 标签色块 + 标记图标 + 时长 + 备注，右侧「改 / 删」。
- 删除时间轴中间条目时，必须弹确认并说明"该段将并入上一环节「X」"或"变为未打标"，不允许静默改变统计口径。
- 深色模式跟随系统（听课教室常较暗）；交互反馈加 12ms 震动；平板 ≥768dp 时标签坞改为 10 列。
- 导出文本示例见报告页。

## 九、技术实现建议（第二阶段安卓工程）

- 语言 **Kotlin + Jetpack Compose**；计时用协程 / `Chronometer`。
- 录音：**MediaRecorder** 采集，音频文件存 App 私有目录（`recordings/`），与 session 绑定；计时暂停时 `pause()` 跟录、恢复时 `resume()`，结束 `stop()` 并关联 session.audio.path。需 `RECORD_AUDIO` 权限，**在开始页随「同时录音」默认勾选项一次性申请**（勾选态持久化，默认开）。
- 录音分段：一次听课可能多次开停录音，须按段落盘（`segments[]` 各含 startElapsed / endElapsed / path），**不得因再次开录覆盖前一段**。
- 录音停止是异步的：`MediaRecorder.stop()` 后要等 `onStop`/`onFinalize` 回调拿到文件，再跳转报告页并渲染播放器；否则会出现"录了音但报告页没有播放器"。
- 时长计算：每个标记其"环节时长"= 下一标记时间戳 − 本标记时间戳；末段 = 结束时刻 − 末标记时间戳。该计算在 UI 实时进行，不落库（源数据只有时间戳）。
- **打标时刻在点击瞬间冻结**（写入 `ts`），弹窗内填写耗时不参与计时，否则每个环节边界都会系统性后移。
- 占比分析：结束后按主标签聚合环节时长，每类占比 = 该类累计时长 / 总计时 × 100%（保留 1 位小数）；**必须单列「未打标」段**（0 → 首个打标），使各类占比之和恒为 100%，可复核。
- 持久化：**Room** 存储 session、marks、audio 索引；结束即写入历史表，不得清空当前再复用同一主键。
- 打标零延迟：14 个环节标签常驻为底部标签坞（Chip 网格），轻点直接落库；BottomSheet 仅用于补充子标签/评课标记/备注。
- 可选增强：后台计时保活、息屏继续、震动反馈、标签自定义管理、录音波形。

## 十二、v1.2 交互评审与缺陷修复记录

### 12.1 交互评审结论（v1.1 → v1.2）

v1.1 的界面观感可用，但存在 6 项**阻断级**问题（会导致数据丢失、流程走死或统计口径失真）与多处效率问题，v1.2 已全部重构。

| 级别 | 编号 | 问题 | v1.2 处理 |
|---|---|---|---|
| 阻断 | A1 | `goClock()` 从未被任何按钮调用，进入时间轴/报告页后**无法回到计时页**（流程走死） | 计时页永不销毁；时间轴改为抽屉覆盖；报告/历史页底栏提供「再听一节」「历史记录」 |
| 阻断 | A2 | 打标时间戳取**保存时刻**，填写弹窗的几十秒被计入前一环节，**环节边界系统性后移** | 打开弹窗瞬间冻结 `editingTs`，弹窗内明确标注"已冻结" |
| 阻断 | A3 | 结束即 `S.marks=[]`、单一 `localStorage` 键，**误点结束 = 数据全丢**，且无法连听两节 | 结束写入 `sessions` 历史表（保留 80 条）；「结束」二次确认并提示已记录条数 |
| 阻断 | A4 | `stop()` 异步，`goReport()` 立即读 `blobUrl` 仍为 null，**真录音永远不出现播放器** | `stopRec()` 返回 Promise，`onStop` 落段后再跳报告页；`endSession` 也返回 Promise |
| 阻断 | A5 | 中途停录再开录时 `chunks=[]` + `blobUrl` 覆盖，**前一段音频静默丢失** | `<audio>` 按段渲染 |
| 阻断 | A6 | 占比按 `ts[i+1]−ts[i]` 聚合，**首个打标前的时间无处归属**，各类占比之和恒小于 100% | 新增「未打标」行，占比之和恒为 100%，并顶部注明计算口径 |
| 效率 | B1 | 打标 = 88vh 模态弹窗 + 4 步 + 必点保存，秒级操作变填表 | 常驻标签坞**一键打标**；弹窗降级为"补充细节" |
| 效率 | B2 | 主按钮在「开始听课 / 打标」间换文案，语义漂移易误触 | 分离：开始页大按钮、计时页标签坞 + 底栏「暂停/结束」 |
| 效率 | B3 | 误标修正需切页找条目（3 步） | 打标后 toast 内嵌「撤销」（5s）；「上一条」卡片直接「补充细节」 |
| 效率 | B4 | 14 个标签平铺 3 列，扫视成本高 | 标签坞 2×7 用短名（导入/目标/讲解/演示/生实/探究/互动/检测/巩固/小结/作业/板书/技术/拓展），长名保留在弹窗 |
| 效率 | B5 | 计时页与时间轴互斥，看不到彼此 | 抽屉式时间轴，计时器常驻 |
| 效率 | B6 | 录音需开始后再点一次，容易漏录 | **开始前默认勾选**，开始即录；未录音时黄色警示条常驻 |

### 13.6 v1.3 真机问题修复（首轮实测反馈）

真机安装试用后反馈 5 个问题，均已定位并修复，产出 `v1.3`：

| # | 现象 | 根因 | 修复要点 |
|---|---|---|---|
| 1 | 熄屏 / 切后台**录音无声** | Android 9 起应用处于后台时麦克风被系统静音；仅靠普通前台进程无法采集 | 新增麦克风类型前台服务（`foregroundServiceType="microphone"`），录音前 `startForegroundService`、结束 `stopService`；补 `FOREGROUND_SERVICE_MICROPHONE`、`POST_NOTIFICATIONS` 权限，并在开始页与录音权限一并申请 |
| 2 | 回到历史记录**打标全部丢失** | `sessions` 表用 `OnConflictStrategy.REPLACE` 保存。SQLite 的 `INSERT OR REPLACE` 实际是「先 DELETE 旧行再 INSERT」，触发 `marks` 的 `ON DELETE CASCADE`，把该节全部打标级联删除；而 `persistSnapshot()` 在每次打标后都会重写 session 行，于是标记边打边被删 | sessions 改用 `@Upsert`（`INSERT … ON CONFLICT DO UPDATE`，不再删行）；并让打标写入先 `join` 掉 session 落库任务，确保父行先存在，避免外键约束失败 |
| 3 | 录音回放**无进度**、播完仍显示"暂停" | 只实现了播放/暂停，缺少时长、进度与完成回调 | `MediaPlayer.prepareAsync` + `onPrepared` 取总时长；`Slider` 支持拖动定位；200ms 轮询当前位置；`setOnCompletionListener` 复位按钮与进度 |
| 4 | 打标提示条**遮挡标签坞** | Toast 定位在底部（距底 116dp），与标签坞重叠 | Toast 移至顶栏下方，任何情况下不再覆盖操作区 |
| 5 | 系统返回键**直接回桌面** | 未拦截返回 | 计时页拦截返回 → 弹「退出听课？」（继续听课 / 结束本节）；历史页返回 → 主页面（听课中则回计时页）；结束后报告 → 主页面；由历史进入的报告 → 历史。历史与报告顶栏另加「‹ 返回」，不只依赖系统手势 |
| 6 | 需求：录音需可**分享 / 导出** | — | 每段录音提供分享（`ACTION_SEND` + FileProvider，系统面板内可存到文件、网盘或发微信）；多段时提供「分享全部录音」（`ACTION_SEND_MULTIPLE`） |

**新增的不变量（后续改动请勿破坏）**：

1. 凡是带子表的父表，**不得**用 `OnConflictStrategy.REPLACE` 更新，否则级联删除会把子数据清空。
2. 需要后台采集麦克风时，必须持有 `microphone` 类型的前台服务，否则静音。
3. 计时页的底部区域（标签坞、操作栏）不得放置任何悬浮提示，提示统一走顶部。
4. 报告页/历史页的 `MediaPlayer` 生命周期绑定 Activity 的 Composition，**不得**再让 Activity 因屏幕旋转而重建。

### 13.7 v1.4 变更（竖屏锁定 + 历史信息可编辑）

真机第二轮反馈：导航、录音、熄屏 10 分钟以上持续录音、分享到微信播放均符合预期。本轮两项调整，产出 `v1.4`。

**① 全竖屏（去掉横屏支持）**

口径：本期只做手机，不支持平板与横屏布局，全部竖屏显示。

- `AndroidManifest.xml`：`MainActivity` 加 `android:screenOrientation="portrait"`。
- `MainActivity.onCreate`：再显式 `requestedOrientation = SCREEN_ORIENTATION_PORTRAIT`，防个别 ROM / 分屏 / 大屏策略忽略 Manifest 声明。
- `android:configChanges="orientation|screenSize|screenLayout|smallestScreenSize|keyboardHidden|navigation"`：兜底，即使系统仍发生配置变化，Activity 不重建。

**为什么这样能修好「自动横屏后录音播放停止并回到开头」**：旋转会重建 Activity，Compose 的 Composition 被销毁，`AudioRow` 里 `MediaPlayer` 走 `onDispose` 被 `release()`，`remember` 保存的播放位置与播放状态一并丢失，重进页面即从头开始。锁竖屏 + `configChanges` 双保险后不再重建，回放状态保持。

- 入口：历史列表每条卡片「编辑信息」；历史报告页顶栏「编辑信息」。

- 保存路径：历史节走 `SessionDao.@Upsert`（`SessionEntity.withInfo(...)` 只覆盖信息字段，行不删除），因此**打标、录音分段、时长全部保留**；正在进行中的本节则更新 `info` 并随快照落库。
- 保存后同步刷新历史列表与报告页表头，报告页导出的文本 / CSV / 占比长图立即使用新信息。
- 只改信息，不改打标与音频：历史打标编辑、补录仍为后续版本考虑项。

**数据库升级（关键）**：Room `version 1 → 2`，新增 4 列（`TEXT NOT NULL` + 默认值），用 `MIGRATION_1_2` 的 `ALTER TABLE … ADD COLUMN` 完成。**不能只靠 `fallbackToDestructiveMigration()`**——那会在升级时清空用户已积累的历史听课记录。已用 SQLite 实测：老记录升级后自动补默认值，打标与录音分段不受影响。

**交互**：信息编辑弹窗的学段/科目改为一行横向可滚动的胶囊单选（避免 15 个科目把弹窗撑爆），选「自定义」才出现自由输入框；打开已有记录时若其值不在列表内，自动进自定义态并回填原文。单位字段在保存时若被清空，回落为默认学校全称。

**展示与导出**：开始页信息卡、计时页/报告页顶栏、历史卡片统一显示「学段+科目 · 班级 · 教师（单位） · 日期 · 节次」；文本报告三行头（课题+学段科目+时长 / 班级·授课姓名（单位）·日期·节次 / 听课人 姓名（单位））；CSV 末尾新增 `学段,科目` 两列，便于跨学段跨学科汇总；占比长图副标题同步。

**新增的不变量**

7. 听课信息的扩展字段一律走 `domain.Info` ↔ `data.SessionEntity` 的 `toInfo()` / `withInfo()` / `toHeader()` 转换，不要在 UI 里手工拼装报告表头。
